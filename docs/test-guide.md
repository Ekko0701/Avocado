# 0.3.1 테스트 가이드

네 가지 조합을 차례로 확인합니다. 순서대로 하면 앞에서 만든 것을 뒤에서 다시 씁니다.

| | API 키 없음 (Claude 앱 방식) | API 키 있음 |
|---|---|---|
| **로컬 워크스페이스** | A | B |
| **GitHub** | C | D |

- **API 키**는 플로우 만들기와 화면 판정을 누가 하느냐만 바꿉니다. 키가 없으면 내 Claude 앱이 하고, 있으면 앱이 API 로 직접 합니다(비용 발생).
- **CLI 실행(재생)은 네 조합 모두 모델을 부르지 않습니다.** 플로우가 없는 TC 를 CLI 로 만드는 것은 아직 없습니다(T-123).

## 0. 준비 (한 번)

1. Avocado 0.3.1 을 설치합니다. 설정 → 앱 정보에 0.3.1 이 보이면 됩니다.
2. 설정 마법사에서 도구(JRE·Maestro)를 설치합니다.
3. 기기 화면의 **iOS 시뮬레이터 준비**로 QA 시뮬레이터를 켭니다.
4. 설정 → **터미널**의 명령을 복사해 터미널에서 한 번 실행합니다. **다시 확인**을 눌러 **연결됨**이 보이면 됩니다.

   ```bash
   avocado qa options
   ```

   앱 버전 0.3.1 과 켠 시뮬레이터가 보이면 준비가 끝난 것입니다.

**시험용 앱.** 따로 빌드하지 않아도 되도록 시뮬레이터에 들어 있는 **설정 앱**을 씁니다. 이름은 `Settings`(폴더·CLI 이름은 자동으로 `settings`), iOS 앱 ID 는 `com.apple.Preferences` 입니다.

## A. 로컬 + API 키 없음 (기본)

설정 → GitHub 에서 **GitHub 사용**이 꺼져 있고, 설정 → Claude 가 **내 Claude 앱**인 상태입니다.

1. **Claude 연결.** 설정 → Claude 에서 Claude 데스크톱 앱에 등록하거나 Claude Code 명령을 실행합니다. 툴바에 "Claude 1" 이 보이면 됩니다.
2. **앱 등록.** 워크스페이스 화면의 **＋ 새 앱**에서 이름 `Settings` 를 쓰면 폴더·CLI 이름이 `settings` 로 채워집니다. iOS 앱 ID 는 `com.apple.Preferences` 입니다.
3. **TC 작성.** 테스트 케이스 화면의 **새 테스트 케이스**. 예: "설정 앱 검색창에 Wi-Fi 를 입력하면 Wi-Fi 항목이 보인다". 태그 `smoke`, 상태 `active` 로 저장합니다.
4. **플로우 만들기.** 플로우 만들기에서 TC 와 시뮬레이터를 고르고 **Claude 로 플로우 만들기** → 요청을 Claude 에 붙여 넣습니다. 끝나면 플로우가 저장됩니다.
5. **앱에서 실행.** 실행 → 테스트 케이스로 실행합니다. 결과 화면에 스텝과 캡처가 보이는지 봅니다.
6. **CLI 실행.** 실행 화면을 열어 둔 채로:

   ```bash
   avocado qa run settings-TC-0001   # 번호는 만든 TC 의 번호
   echo $?
   ```

   - [ ] 종료 코드 0, 요약에 "통과"
   - [ ] 실행 화면에 "터미널에서 시작(avocado-cli 0.1.0)"이 보임
   - [ ] 결과 화면에 그 실행이 생김

7. **CLI 의 다른 경우.**

   | 해 볼 것 | 기대 |
   |---|---|
   | 두 번째 TC 를 태그 `smoke`·`active` 로, 플로우 없이 저장하고 `avocado qa run settings-TC-0002` | 종료 코드 5, "플로우가 없다" |
   | `avocado qa run --app settings --tag smoke` | 플로우 있는 것만 돌고, 없는 것은 "건너뜀". 종료 코드 5 |
   | 실행 중에 Ctrl-C | "취소를 요청했다", 종료 코드 4 |
   | 앱에서 차례 실행을 돌리는 동안 CLI 로 시작 | 종료 코드 6, "다른 차례 실행이 진행 중" |
   | `avocado qa run settings-TC-9999` | 종료 코드 2 |
   | 앱을 끄고 `avocado qa options` | 종료 코드 3 |
   | `avocado qa run settings-TC-0001 --json` | 표준 출력이 JSON 하나 |

8. **증적 내보내기.** 결과 → **폴더로 내보내기**로 요약 묶음을 만들어 봅니다.

## B. 로컬 + API 키 있음

1. 설정 → Claude → **Anthropic API 키**로 바꾸고 키를 넣습니다. 시험 중에는 **월 비용 상한**을 $5 정도로 낮춥니다.
2. **플로우 만들기.** 새 TC 로 **플로우 만들기**를 누르면 Claude 앱 없이 앱이 직접 만듭니다. 설정 → Claude 의 이번 달 비용이 늘어나는지 봅니다.
3. **자동 화면 판정.** **자동 화면 판정 비율**을 1 로 두고:
   - [ ] 앱 실행 화면에서 실행 → 결과 화면에 판정이 붙음(비용 발생)
   - [ ] `avocado qa run …` 으로 실행 → 판정이 붙지 않음, 비용이 늘지 않음
   - [ ] CLI 실행도 결과 화면의 **Claude 로 화면 판정**을 누르면 판정됨
4. 끝나면 비율을 0 으로 돌리거나 **내 Claude 앱**으로 돌아갑니다.

## C. GitHub + API 키 없음

1. 설정 → GitHub 에서 **GitHub 사용**을 켜고 토큰과 저장소를 넣습니다. 로컬 워크스페이스와 폴더가 따로라 A·B 에서 만든 것은 보이지 않습니다. 필요하면 워크스페이스 내보내기·가져오기로 옮깁니다.
2. **TC 저장.** 저장(커밋)하면 그 TC 의 작업 브랜치에 커밋되고 **PR 작성**이 보입니다.
3. **플로우 만들기.** A 의 4번과 같습니다. 플로우도 작업 브랜치에 저장됩니다.
4. **CLI 실행.** CLI 는 **지금 앱이 열어 둔 브랜치**의 플로우를 돌립니다.
   - [ ] 플로우를 만든 직후(작업 브랜치)에 `avocado qa run …` → 실행됨
   - [ ] PR 을 머지하고 main 을 받은 뒤 → 실행됨
   - [ ] 머지하지 않고 main 으로 바꾼 상태 → 종료 코드 5(그 브랜치에만 플로우가 있음)
5. **증적 올리기.** 설정 → 증적의 업로드 정책이 켜져 있으면 결과 화면에 **증적 올리기** 탭이 나옵니다. 폴더로 내보내기도 그대로 됩니다.

## D. GitHub + API 키 있음

B 를 GitHub 방식에서 한 번 더 합니다. 다른 점은 플로우가 작업 브랜치에 저장된다는 것뿐입니다.

## 문제가 생기면

- 화면의 오류 문구, 실행한 명령과 종료 코드를 알려 주세요.
- 로그는 `~/Library/Application Support/Avocado/logs` 에 있습니다(`claude.log` 는 Claude·CLI 연결).
- 실행 결과는 결과 → **폴더로 내보내기**로 묶어 주면 비밀 값을 가린 채 볼 수 있습니다.
