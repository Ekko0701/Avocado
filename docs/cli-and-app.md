# avocado 명령(CLI)과 앱의 관계

터미널의 `avocado` 명령이 어떻게 동작하는지, 왜 앱이 켜져 있어야 하는지 정리합니다.

## 한눈에

```
터미널 avocado 명령 ─┐
Claude Code        ─┼─ MCP(앱 소켓) ─▶ Avocado 앱 ─▶ 기기·Maestro·DB·증적
Claude Desktop     ─┘
```

- **Avocado 앱**: 실제로 실행하는 곳입니다. 기기, DB, 비밀 값, 워크스페이스를 앱 하나가 가집니다.
- **MCP**: 앱과 대화하는 통로입니다. CLI 와 Claude 가 같은 통로를 씁니다.
- **CLI**: 사람과 CI 가 쓰는 버튼입니다. 앱에 부탁만 합니다.

## 앱이 켜져 있어야 하나요?

네. 앱이 꺼져 있으면 CLI 는 종료 코드 3 으로 끝납니다. CLI 혼자 실행하지 않는 이유는 넷입니다.

1. **비밀 값**: 테스트 계정 비밀번호와 API 키는 앱만 풀 수 있게 암호화돼 있습니다(키는 macOS 키체인).
2. **한 번에 하나**: "이 기기는 실행 중" 같은 표시를 앱이 메모리에 들고 있습니다. CLI 가 따로 돌면 같은 기기에 실행이 겹칩니다.
3. **앱이 하던 일**: 실행 서비스를 따로 띄우면 시작할 때 진행 중인 작업을 실패로 바꾸고, 같은 기기의 Maestro 드라이버를 끕니다.
4. **워크스페이스**: 두 프로세스가 같은 폴더에서 브랜치를 바꾸고 파일을 쓰면 작업 트리가 섞입니다.

## CLI 가 있는데 MCP 가 필요한가요?

필요합니다. CLI 도 MCP 위에서 돌아갑니다.

- Claude Desktop 은 터미널 명령을 못 돌리고 MCP 도구만 부릅니다.
- 플로우 만들기는 화면 보기와 시도를 수십 번 주고받아서 CLI 명령으로 쪼개기 어렵습니다.
- 앱은 MCP 도구 안에서 안전 규칙을 지킵니다: Claude 에게 셸을 주지 않고, 화면 글자를 지시로 따르지 않고, 비밀 값을 가리고, 호출 횟수를 제한합니다.

## 플로우가 없는 테스트 케이스 (계획, T-123)

지금 CLI 는 플로우가 있는 테스트 케이스만 실행하고, 없으면 종료 코드 5 로 알립니다. 계획은 이렇습니다.

| 상황 | 동작 |
|---|---|
| Anthropic API 키가 있음 | `avocado qa run` 한 줄로 만들기부터 실행까지 자동. CI 에서도 된다 |
| 키가 없고 Claude Desktop·Claude Code 가 있음 | CLI 가 Claude 를 요청 문장이 채워진 채로 연다. Enter 한 번이면 Claude 가 만들고 CLI 가 이어서 실행한다 |
| 키가 없고 사람이 없음(CI) | 지금처럼 종료 코드 5 |

반대 방향도 됩니다. Claude Code 나 Claude Desktop 에 "demo-TC-0101 플로우 만들고 돌려 줘"라고 보내면 Claude 가 Avocado 의 MCP 도구로 끝까지 진행합니다. 키가 없어도 됩니다. 이를 위해 Claude 가 플로우 만들기를 직접 시작하는 도구를 더합니다(지금은 앱 화면에서만 시작).

Enter 없이 완전 자동으로 하는 길은 `claude -p` 를 대신 띄우는 것뿐입니다. Anthropic 약관이 제3자 앱이 사용자 구독으로 요청을 보내는 것을 막고 있어 쓰지 않습니다.
