# 터미널에서 실행하기

Avocado 앱이 켜져 있으면 터미널에서 `avocado` 명령으로 테스트 케이스를 실행할 수 있습니다. 실행은 앱이 하고, 결과와 증적은 앱에서 실행한 것과 똑같이 **결과** 화면에 남습니다. CI 나 스크립트에서 쓸 때는 `--json` 과 종료 코드를 봅니다.

## 1. 명령 걸기 (한 번만)

명령은 앱 안(`Avocado.app/Contents/Resources/bin/avocado`)에 들어 있습니다. **설정 → 터미널**에서 거는 명령을 복사해 터미널에 붙여 넣습니다. `/Applications` 에 설치했다면 이렇습니다.

```bash
mkdir -p ~/.local/bin && ln -sf '/Applications/Avocado.app/Contents/Resources/bin/avocado' ~/.local/bin/avocado
```

- 실행한 뒤 **다시 확인**을 누르면 **연결됨**으로 바뀝니다.
- `~/.local/bin` 이 PATH 에 없으면 `~/.zshrc` 에 `export PATH="$HOME/.local/bin:$PATH"` 를 넣고 터미널을 새로 엽니다.
- Avocado 는 앱 데이터 밖에 파일을 만들지 않습니다. 명령을 거는 것은 직접 합니다.
- 앱을 같은 자리에 다시 설치하거나 업데이트하면 다시 걸지 않아도 됩니다.

## 2. 쓰기

```bash
avocado qa options                                  # 테스트 케이스, 준비된 기기, 빌드
avocado qa run demo-TC-0101 --device <기기 id>       # 실행하고 끝까지 따라간다
avocado qa run demo-TC-0101 demo-TC-0102            # 여러 개를 차례로
avocado qa run --app demo --tag smoke --json        # 태그로, 결과는 JSON
avocado qa status <묶음 id>                          # 다른 터미널에서 따라가기
avocado qa cancel <묶음 id>                          # 취소
```

- 테스트 케이스는 `<앱>-TC-<번호>` 또는 `<앱>/TC-<번호>` 로 씁니다.
- 기기를 빼면 준비된 기기가 하나일 때만 그 기기로 실행합니다. 여럿이면 후보를 보여 주고 멈춥니다.
- `Ctrl-C` 는 이 명령이 시작한 실행만 취소하고 끝날 때까지 기다립니다.
- 플로우가 있는 테스트 케이스만 실행합니다. 플로우는 앱의 **플로우 만들기**에서 먼저 만듭니다.
- 실행은 한 번에 한 묶음입니다. 앱에서 차례 실행이 도는 동안에는 시작하지 않습니다.
- 진행은 화면(stderr)에, 요약과 `--json` 결과는 표준 출력(stdout)에 나옵니다.

## 3. 종료 코드

| 코드 | 뜻 |
|---|---|
| 0 | 모두 통과 |
| 1 | 실패한 실행이 있음 |
| 2 | 인자 오류(없는 앱·테스트 케이스, 기기가 여럿) |
| 3 | 앱에 연결하지 못함(앱이 꺼져 있거나 도중에 꺼짐) |
| 4 | 취소 |
| 5 | 플로우가 없어 실행하지 않은 테스트 케이스가 있음 |
| 6 | 시작하지 못했거나 오류(기기가 준비되지 않음, 다른 실행이 도는 중) |

여러 개에 해당하면 위에서부터 앞선 것(3, 2, 6, 4, 1, 5 순서)이 나옵니다.
