# Avocado 설치와 첫 실행

기획자·QA 가 자기 Mac 에 Avocado 를 설치하고, 첫 플로우를 실행해 결과를 보기까지의 순서다. 30~60분(Xcode 설치 시간 제외).

## 1. 준비물

| 항목 | 내용 |
|---|---|
| Mac | Apple Silicon(M1 이상). Intel Mac 은 아직 지원하지 않는다 |
| Xcode | App Store 에서 설치 → 한 번 열어 추가 구성 요소 설치에 동의(사람이 직접) |
| iOS 시뮬레이터 런타임 | Xcode → Settings → Components 에서 iOS 런타임 설치 |
| 디스크 | 앱 약 400MB + Maestro·Java 약 360MB + 시뮬레이터 |
| GitHub 계정 | 워크스페이스·증적 저장소에 쓸 수 있는 계정(개인 계정 또는 조직 멤버). 토큰 발급은 아래 3절 |
| Claude | 플로우 자동 작성은 각자 쓰는 Claude 데스크톱 앱이나 Claude Code 로 한다([내 Claude 로 플로우 만들기](claude-connect.md)). API 키는 화면 판정이나 API 키 방식을 고를 때만 |
| Android(선택) | Android 대상을 돌릴 때만 Android Studio 의 SDK·에뮬레이터 |

약관·라이선스 동의는 모두 사람이 직접 한다. 앱은 대신 동의하지 않는다.

## 2. 앱 받기와 설치

1. [Avocado Releases](https://github.com/Ekko0701/Avocado/releases) 에서 `Avocado-<버전>-arm64.dmg`와 `Avocado-<버전>-arm64.dmg.sha256`을 받는다.
2. 파일이 온전한지 확인한다. 두 줄의 해시가 같아야 한다.

   ```bash
   shasum -a 256 ~/Downloads/Avocado-*-arm64.dmg
   ```

   ```bash
   cat ~/Downloads/Avocado-*-arm64.dmg.sha256
   ```

3. dmg 를 열고 Avocado 를 응용 프로그램 폴더로 끈다.

### 첫 실행 보안 경고 (서명 없는 내부 빌드일 때)

정식 릴리스는 Developer ID 로 서명·공증돼 경고 없이 열린다. Releases 에 "미리보기"로 표시된 서명 없는 빌드만 "확인되지 않은 개발자" 경고가 뜬다.

1. Avocado 를 한 번 열어 경고를 띄우고 닫는다.
2. 시스템 설정 → 개인정보 보호 및 보안 → 아래쪽 보안 항목에서 "Avocado" 옆 **그래도 열기**를 누르고 암호를 입력한다.
3. 다시 연다. 이후로는 경고가 없다.

해시가 다르거나 출처를 모르는 dmg 는 열지 않는다. 서명된 정식 빌드가 나오면 이 절차는 필요 없다.

## 3. GitHub 토큰 발급

GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token.

- Resource owner: 저장소의 주인(개인 계정 또는 조직)
- Repository access: 워크스페이스 저장소, 올해 증적 저장소(`…-<연도>`). 새 버전 확인은 공개 배포 저장소를 보므로 토큰에 넣지 않아도 된다
- Permissions(Repository): Contents **읽기·쓰기**, Pull requests **읽기·쓰기**, Metadata 읽기
- 만료: 필요한 기간으로 정한다. 조직 저장소면 조직 정책을 따른다(만료되면 설정에서 새 토큰으로 바꾼다)

토큰은 앱이 macOS 키체인 키로 암호화해 이 Mac 에만 둔다. 화면에 다시 보이지 않고 파일·로그에도 평문으로 남지 않는다.

## 4. 설정 마법사

처음 열면 마법사가 뜬다. 나중에 왼쪽 메뉴 "설정 마법사"로 다시 열 수 있다.

1. **Claude 연결**: 플로우 만들기·화면 판정은 각자 쓰는 Claude(데스크톱 앱·Claude Code)가 한다. 데스크톱 앱은 **Claude 데스크톱 앱에 등록**, Claude Code 는 보이는 명령을 터미널에서 한 번 실행한다([내 Claude 로 플로우 만들기](claude-connect.md)). API 키 방식을 고를 때만 Anthropic API 키를 넣는다. 나중에 설정에서 해도 된다.
2. **GitHub 토큰**: 3절에서 만든 토큰.
3. **환경 점검·도구**: macOS·Xcode·시뮬레이터 런타임·git 을 점검하고, 앱이 쓰는 Java(JRE)와 Maestro 를 정해진 버전으로 내려받아 체크섬을 확인한 뒤 설치한다(약 360MB). 사용자의 다른 Maestro 설치와 섞이지 않는다. "Maestro 확인"이 통과해야 한다.
4. **GitHub·워크스페이스**: **저장소 목록 불러오기** → 토큰으로 볼 수 있는 저장소에서 워크스페이스(TC·플로우)와 연도로 끝나는 증적 저장소(예: `…-2026`)를 고르고 **고른 저장소로 저장** → 로그인 이름과 저장소 권한이 보이면 **워크스페이스 연결(clone)**. 저장소 이름은 사람마다 달라도 된다. 건너뛰고 5절에서 해도 된다.
5. **QA 기기**: **iOS 시뮬레이터 준비**(1~3분). 건너뛰고 6절에서 해도 된다.
6. **완료**.

macOS 가 키체인 접근을 물으면 "항상 허용"을 누른다(비밀 값 암호화에 쓴다).

## 5. GitHub·워크스페이스 연결 (마법사에서 건너뛰었을 때)

1. 설정 → GitHub: **저장소 목록 불러오기**로 저장소를 고르고 **고른 저장소로 저장**(목록에 없으면 아래 칸에 조직·저장소 이름을 직접 넣고 저장) → **연결 확인**. 로그인 이름과 저장소별 권한이 보이면 된다.
2. 워크스페이스 메뉴 → **연결(clone)**: 고른 워크스페이스 저장소를 앱 데이터 폴더에 받는다. TC·플로우는 여기서 읽고, 고친 것은 작업 브랜치와 PR 로만 올라간다(main 에 바로 올리지 않는다).
3. 설정 → 테스트 계정 값: 워크스페이스를 연결하면 앱마다 `apps/<앱>/accounts.yaml`에 적힌 키가 줄로 나온다(역할·설명, 저장 여부). 값만 넣고 **저장**한다. 워크스페이스에 없는 키는 "직접 추가"로 넣는다. 실행할 때만 앱이 꺼내 Maestro 에 넘기고, 증적에서는 가린다. 실제 사용자 계정이 아니라 테스트 계정만 쓴다.

## 6. 기기와 빌드 (기기는 마법사에서 건너뛰었을 때)

1. 기기 메뉴 → **iOS 버전**과 **기종**(iPhone·iPad)을 고르고 **iOS 시뮬레이터 준비**: 앱 전용 시뮬레이터(예: `Avocado iPhone 17 (iOS 27.0)`)를 만들고 설정의 기기 언어(ko_KR)로 맞추고 동작 줄이기를 켜서 부팅한다. 같은 기종·버전이 이미 있으면 다시 쓴다.
   - 고를 수 있는 iOS 버전은 이 Mac 에 설치된 iOS 런타임이다. 다른 버전이 필요하면 Xcode → Settings → Components 에서 설치한다.
   - 여러 기기를 켜 두면 실행·플로우 만들기에서 그중 하나를 고른다.
   - Android 는 **AVD** 를 고르고 **Android 에뮬레이터 준비**. AVD 는 Android Studio 의 Device Manager 에서 만든다.
   - 앱이 만든 시뮬레이터는 **삭제**(한 번 더 확인)로 지운다. 그 안에 설치한 앱·데이터도 지워진다. 직접 만든 시뮬레이터는 목록에 나오지 않고 앱이 건드리지 않는다. 실행·플로우 만들기 중에는 지우지 않는다.
2. 빌드 메뉴 → 앱 ID(예: `myapp`)를 고르고 테스트할 앱을 넣는다. 등록한 빌드는 앱 데이터 폴더로 복사된다.
   - **프로젝트로 빌드**(iOS, 가장 쉬움): **프로젝트 연결**로 Xcode 프로젝트 폴더(또는 `.xcworkspace`·`.xcodeproj`)를 고르고, 스킴·구성을 골라 **빌드 시작**. Avocado 가 시뮬레이터용으로 빌드해 등록한다(첫 빌드는 몇 분).
     - 폴더 위치는 이 Mac 에만 저장한다. 지금 폴더의 코드(커밋하지 않은 변경 포함)로 빌드하고, 빌드 기록에 커밋을 남긴다.
     - Tuist·XcodeGen·CocoaPods 프로젝트는 빌드 전에 프로젝트 폴더에서 생성·`pod install` 을 한다. 해당 도구가 설치돼 있어야 한다.
     - 팀이 같이 쓰는 스킴·구성은 워크스페이스 → 앱 설정의 **iOS 빌드 기본값**에 적어 두면 자동으로 골라진다.
     - 스킴 목록이 비면 Xcode 의 Product → Scheme → Manage Schemes 에서 그 스킴의 **Shared** 를 켠다.
   - **파일로 등록**: 직접 빌드한 시뮬레이터용 `.app` 폴더나 `.apk` 를 고른다.
   - **빌드 스크립트 실행**: 빌드 과정이 특별한 팀이 준 스크립트를 고른다.

## 7. 첫 실행

1. 실행 메뉴 → **플로우 선택**: 워크스페이스의 `flows/<앱>/ios/TC-xxxx.yaml`을 고른다.
2. 빌드와 기기를 고르고 **실행**. 실패하면 한 번 다시 실행하고, 다시 통과하면 "불안정"으로 표시한다.
3. 결과 메뉴: TC × 타깃 표에서 실행을 누르면 스텝 타임라인, 실패 스텝 캡처, 로그의 실패 줄이 바로 보인다. 화면에 보이는 증적은 비밀 값을 가린 사본이다.

앱에 테스트 서버가 필요하면 실행 전에 먼저 띄운다.

## 8. 자주 묻는 것

| 증상 | 할 일 |
|---|---|
| "드라이버가 시작하지 못했다"(환경 문제) | 시뮬레이터를 다시 부팅하고 다시 실행한다. Mac 이 바쁘면 시간 초과가 날 수 있다 |
| 키체인 암호화를 쓸 수 없다 | 로그인 키체인이 잠겨 있지 않은지 확인한다. 앱은 평문으로 대신 저장하지 않는다 |
| GitHub 연결 확인 실패 | 토큰 만료·저장소 선택·권한(Contents·Pull requests 쓰기)을 확인한다 |
| 새 버전 배너가 뜬다 | **받기**를 누르면 SHA-256 과 서명을 확인한 뒤 연다. 서명 없는 빌드는 Finder 에서만 보여 준다(2절 절차로 설치) |
| 증적 올리기 버튼이 없다 | 조직 보안 승인(D11) 전에는 숨겨진다. 운영자가 설정 → 조직 정책에서 켠다 |

앱 데이터 폴더: `~/Library/Application Support/Avocado`(DB, 증적, 워크스페이스, 도구, 로그). 원본 증적은 이 Mac 에만 있다.
