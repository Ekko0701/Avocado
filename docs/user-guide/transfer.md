# 테스트 케이스 건네기와 GitHub 로 옮기기

로컬 워크스페이스는 이 Mac 에서 혼자 쓴다. 팀원에게 테스트 케이스를 건네거나, 로컬에서 쓰던 것을 GitHub 워크스페이스로 올릴 때는 워크스페이스 메뉴 → **내보내기·가져오기**를 쓴다. 자동으로 맞춰 주지 않는다. 그때그때 사람이 내보내고 가져온다.

## 팀원에게 건네기

### 보내는 사람: 내보내기

1. 워크스페이스 → **내보내기·가져오기** → **내보내기** 탭을 연다.
2. 들어가는 것(앱 설정, 테스트 케이스, 플로우, 공통 서브플로우)의 개수를 확인하고 **zip 으로 저장…** 을 누른다. 저장할 곳은 저장 창에서 고른다.
3. 만든 zip 을 메신저나 공유 폴더로 건넨다.

zip 에는 `workspace.yaml` 과 `apps/` 아래 파일만 들어간다.

- 테스트 계정 값은 들어가지 않는다. 키 이름만 들어간다. 받는 사람이 자기 Mac 의 테스트 계정 화면에서 값을 넣는다.
- 실행 기록·증적·등록한 빌드는 들어가지 않는다. 증적은 결과 화면에서 따로 건넨다.
- 플로우 정보(meta)에는 플로우를 만들 때 쓴 기기 이름과 빌드 번호가 있다.
- GitHub 워크스페이스에서 내보내면 `main` 의 내용이 들어간다. 작업 브랜치의 머지하지 않은 수정은 들어가지 않는다.

### 받는 사람: 가져오기

1. 워크스페이스 → **내보내기·가져오기** → **가져오기** 탭에서 **zip 고르기…**(풀어 둔 폴더면 **폴더 고르기…**)를 누른다.
2. 앱이 zip 을 풀지 않고 읽어 이 워크스페이스와 견준 표를 보인다. 플로우마다 Maestro 문법 검사를 해서 조금 걸린다. 설정 마법사에서 Maestro 를 설치해 두어야 한다.
3. 항목마다 상태를 보고 가져올 것을 고른다.

   | 상태 | 뜻 | 처음 값 |
   |---|---|---|
   | 새로 생김 | 이 워크스페이스에 없다 | 가져온다 |
   | 번호 바꿈 | 같은 번호의 다른 테스트 케이스가 이미 있다. 새 번호로 가져오고 파일 이름, 머리말의 `id`, 플로우의 `name` 과 `tags`, meta 의 `tc` 를 함께 바꾼다 | 가져온다 |
   | 내용 다름 | 같은 앱에 같은 번호(또는 같은 서브플로우·앱 설정)가 있고 내용이 다르다. **비교 보기**로 차이를 본다 | 테스트 케이스는 고르지 않는다. 고르면 "같은 테스트, 덮어쓰기"와 "다른 테스트, 새 번호로" 중에서 정한다. 서브플로우는 이 워크스페이스 것을 그대로 둔다 |
   | 같음 | 내용이 같다 | 가져올 것이 없다 |
   | 받지 않음 | 검사에 걸렸다. 이유와 줄 번호가 보인다 | 고를 수 없다 |

4. **고른 항목 N개 가져오기**를 누른다. 고른 항목만 한 번에 저장한다(변경 내역에 커밋 하나).

알아 둘 것:

- 테스트 케이스가 부르는 공통 서브플로우가 이 워크스페이스에 없으면 함께 들어간다. 이 워크스페이스에 없는 앱이나 타깃의 테스트 케이스는 그 앱 설정과 함께 들어간다.
- 앱 설정은 더하기만 한다. 이 워크스페이스의 타깃·역할·키는 지우지 않는다. 같은 타깃의 앱 ID 가 다르면 "내용 다름"으로 보이고 처음에는 이쪽 것을 그대로 둔다.
- 워크스페이스 파일 모양이 아닌 파일(README 등)은 **건너뛴 파일**에 이유와 함께 보인다.
- 받은 플로우는 기기를 움직이고 그 앱의 테스트 계정 값을 받는다. 앱은 이 Mac 의 플로우 검사를 통과한 것만 쓴다. 다른 앱을 띄우는 명령, 스크립트 실행, 워크스페이스 밖을 가리키는 경로 같은 것은 받지 않는다.
- 실행이나 플로우 만들기가 진행 중이면 끝난 뒤 가져온다.

### zip 전체를 받지 않을 때

아래 같은 항목이 하나라도 있으면 zip 전체를 거절하고 이 Mac 에는 아무것도 쓰지 않는다. 화면에 거절한 이유가 보인다.

- 심볼릭 링크, 일반 파일이 아닌 항목
- `..` 이나 `/` 로 시작하는 경로, 역슬래시가 든 이름, ASCII 가 아닌 이름
- 대소문자만 다른 두 이름
- 암호를 건 항목, 지원하지 않는 압축 방식
- 항목 2000개 초과, 파일 하나가 풀면 1MB 초과, 모두 풀면 20MB 초과
- 예전 폴더 구조(schemaVersion 1)의 워크스페이스

보낸 사람에게 Avocado 의 내보내기로 다시 만들어 달라고 하면 이런 항목이 들어가지 않는다.

## 로컬에서 쓰던 것을 GitHub 로 올리기

**GitHub 사용**을 켜도 로컬 내용은 저절로 옮겨지지 않는다. 로컬 워크스페이스는 이 Mac 에 그대로 있고, 가져오기로 골라 PR 로 올린다.

1. 설정 → GitHub 에서 **GitHub 사용**을 켜고 워크스페이스를 연결한다([설치와 첫 실행](install.md) 5절).
2. 툴바의 **동기화**로 `main` 을 원격과 맞춘다. `main` 이 원격보다 뒤처져 있으면 가져오지 않는다.
3. 워크스페이스 → **내보내기·가져오기** → **가져오기** 탭에서 가져올 곳을 **이 Mac 의 로컬 워크스페이스**로 두고 **견주어 보기**를 누른다. GitHub 워크스페이스의 `main` 과 견준다. 받은 zip 이나 폴더도 같은 방법으로 가져올 수 있다.
4. 항목을 고르고 **고른 항목 N개 가져오기**를 누른다. 새 가져오기 브랜치(`qa/<로그인>/import/<요약>`)에 커밋 하나로 들어간다. 지금 작업 폴더와 브랜치는 바뀌지 않는다. 가져올 때마다 새 브랜치를 만든다.
5. 결과 카드의 **PR 작성**으로 PR 을 올린다. **나중에**를 눌렀으면 툴바의 Git 상태에서 "가져오기" 브랜치의 PR 을 작성한다.

PR 을 머지하고 동기화할 때까지 가져온 테스트 케이스·서브플로우·앱 설정은 고칠 수 없다. 테스트 케이스 화면에 "가져오기 PR 을 머지할 때까지 고칠 수 없습니다"와 **PR 열기**가 보인다. 머지 전에 고치면 `main` 에서 갈라진 브랜치에 가져온 앱 설정이 없어 플로우 만들기가 실패하기 때문이다.
